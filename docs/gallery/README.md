## 本次确认什么

确认 Gallery 第一版的产品范围、数据结构、资源集成边界、设计交付方式和分阶段验收标准。本文档集已获用户确认，是后续实现的基线，不是已实现功能说明。工程进度见交付状态。

Gallery 是独立的摄影相册与游记展示平台。Immich 集中管理全部原片及元数据，Gallery 从允许访问的 Immich Asset 中跨相册选片，建立自己的相册树，编写自己的相册游记、照片标题和描述，发布到独立前台。

## 已确认的需求与本轮拟定规则

用户已经明确：独立 Gallery 用户体系与域名；跨 Immich 相册选片；Gallery 自己的相册及图文内容；父子相册；GPS 从 Immich 自动更新；简洁而有设计感的 PC 和移动体验；同库不同 schema；持续合并 Immich 上游。

本轮整体方案确认包含以下具体规则：

1. MVP 开放管理员登录，公众免登录浏览；访客注册、留言评价后续实现。
2. 相册树为单父级，允许每层同时有直接照片和子相册；父相册详情不默认铺开所有后代照片，地图会汇总后代照片。
3. 一个 Asset 可在多个 Gallery 相册出现，各自维护标题、描述；单相册内不重复选同一 Asset。
4. 发布必须沿父级自顶向下；任何祖先下线都会阻止整条后代分支被访问。恢复父级时提示会恢复访问的后代。
5. Gallery 文案、选片、层级和位置公开策略走发布流程；GPS 自动读取最新值，刷新地图更新，无需重发相册。
6. 位置默认隐藏。用户可明确选择精确或近似位置；近似模式规则见集成文档。
7. 相册首次发布后固定 slug。标题和父级可以修改，地址不随层级移动变化。
8. 站点介绍与首页配置采用“保存并应用”，本期不提供站点级草稿；相册有完整草稿预览。
9. 资源所有者白名单为空时不能选片或公开图片；允许访问的 Immich 所有者在初始化时显式配置。

## 文档独立管理

- `docs/gallery/` 是 Gallery 文档的唯一主入口，独立于 Immich 官方文档目录 `docs/docs/`，本期不接入其 Docusaurus 站点。
- 正式开发后与 Gallery 代码一起进入产品分支；不会为了更新 Gallery 文档修改上游文档导航。
- 文档分别标记“待确认／已确认／已实现”，产品范围与交付状态分开记录。
- 架构变更新增编号决策，保留被替代决策；需求、数据字典、迁移和验证说明在同一个功能变更中同步更新。
- 迁移文件是结构执行依据，数据字典负责解释设计。数据库变更必须同时更新这两处。
- 不记录密码、会话令牌、生产密钥或真实私有资产清单。示例使用虚构内容。
- 前次的 [Immich 数据字典](../docs/developer/database-schema-reference.zh-CN.md) 保留为上游结构参考；Gallery 表只在本目录说明。
- 初始化、测试、部署、备份恢复与升级操作手册在相关功能实现时补充实际可执行步骤。本轮计划中的未来命令不是已验证脚本。
