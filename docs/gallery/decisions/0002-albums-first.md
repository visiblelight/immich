# ADR 0002：以相册浏览为中心，收窄首版公共页面

状态：产品调整来自用户明确要求；修订后的视觉预览待用户评审。2026-09-11。

## 依据与决定

用户认为阶段 C 的画册／展览方案个性过强。当前需求是常规、清晰、以浏览照片为主的相册网站。

1. 一级页面仅“相册”和“关于”。首页暂缓，未来再确定内容；地图展示页明确移出 MVP。MVP 根地址进入相册目录。
2. 相册目录采用固定列数网格，不使用瀑布流。列数随屏幕宽度改变，同一断点内整齐排列。
3. 相册详情：桌面左侧子相册和本册照片列表，右侧详细介绍。介绍保留富文本能力，只包含文字，不再插入单图／双图。
4. 点照片进入尽可能大的完整画面，附带 Gallery 标题、描述与 EXIF 参数。信息可隐藏；不把全部 EXIF 原样公开，位置策略仍约束 GPS。
5. 移动延续相同内容关系。此轮预览用两列相册／照片，介绍在照片区上方可展开；看图器默认收起信息，需要时展开底部信息区。具体呈现待评审。
6. 关于页先提供静态文章示例；后续从后台文章模块挑选一篇展示。文章表、选篇关系、文章发布规则与后台范围在后续设计中确定，本轮不创建表或假装完成文章功能。

## 对已完成工程的影响

- 不重新初始化 Git，不修改已执行迁移，不删除已经验证的首页／位置字段及适配器。以后若清理旧字段或新增文章表，使用新迁移并同步数据字典。
- GPS 最新读取、祖先发布权限、来源白名单和媒体权限能力保留。地图能力属于未来扩展，既有阶段 B 测试记录仍有效，但不是本轮地图页面已交付。
- `site.about_document` 是已有结构事实，不再代表“关于”最终文章选择机制；`homepage_item` 与主视觉字段首版不接入 UI。
- 相册富文本的应用层块白名单后续收紧为文字块。数据库现有 JSON 对象结构无需因预览改动而重建。
- 旧 A/B 方案和截图作为历史留存，不再要求用户二选一。当前 `/design` 改为新的相册浏览预览。

## 当前交付与后续

本轮只更新交互预览和范围文档。先确认相册目录、详情、看图器和关于页的基本布局，再继续后台编辑与真实数据接入。此前 ADR 0001 中独立用户、跨 Immich 相册选片、Gallery 相册树、发布与 Git 边界继续适用；冲突的公共页面范围以本决策为准。
