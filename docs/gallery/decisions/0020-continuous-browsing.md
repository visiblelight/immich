# ADR 0020：相册与相片连续浏览

状态：用户于 2026-10-18 确认方案，并授权先在本地实现、查看效果。实际验证及发布状态见[交付记录](../delivery/continuous-browsing.md)。

2026-11-07 范围调整：用户明确子相册数量有限，要求一次完整展示，并移除“已显示全部相册”提示。相册详情的直接子相册不再分页或滚动追加，仍保留排序；旧 `albumsPage`、`albumAfter` 链接返回完整子相册。以下连续浏览规则继续适用于相册总览、相册内照片与全部相片页；不一次加载子相册内的照片。见[本地交付记录](../delivery/child-albums.md)。

## 已确认范围

- 前台相册总览、子相册列表、相册内照片及照片组、全部相片页，改为向下滚动自动追加，保留已有网格和筛选/排序风格。
- 接近列表底部时提前请求下一批。现有内容保持原位，加载期间显示占位；失败保留已加载内容并提供重试，结束时显示完成提示。提供可用键盘操作的加载入口和回到顶部。
- 筛选、搜索、排序变化后重新开始对应列表，取消旧请求，防止结果串入。
- 照片组作为一个完整列表项目加载。大图切换接近末尾时预取，越过批次边界后继续浏览。
- 刷新、返回列表时尽量恢复当前浏览位置。保留既有页码、照片直链和照片锚点的兼容入口；新浏览使用游标续取及可见项目锚点。
- 首屏和追加响应只传当前批次，避免一次下发整册照片资料；每次请求继续执行现有发布资格、祖先、来源、媒体和隐私规则。
- 不在首版引入复杂的虚拟网格。浏览历史缓存有容量与时限；较大图库的长期 DOM 占用和数据库聚合开销另行测量优化。

## 边界

本次不改变后台相册管理/选片分页，不更改 Immich，不修改生产数据库。用户的本地体验反馈仍是发布前的视觉验收步骤。
