# ADR 0001：Gallery 第一版产品与集成边界

日期：2026-09-10。状态：接受，用户已确认。

## 背景

用户以 Immich 集中保存修图成片、手机备份及家庭私密照片，在其中管理相册、标签和 GPS。Gallery 用于自己策划的公开旅行相册，内容类似带照片集合的游记文章。用户要求设计品质、独立账号与域名、相册嵌套，以及后续合并 Immich 上游。

## 决定

1. 同仓库、独立 Gallery 模块；同数据库、独立 gallery schema；通过只读适配层取 Immich Asset。
2. Gallery Album 是一级内容对象，来源可跨多个 Immich 相册，Immich Album 仅用于后台过滤。
3. 一张照片在不同 Gallery Album 中有独立标题和描述；建立 album_photo 关系对象。
4. 相册树为单父级，草稿树和当前发布树分开，发布前验证最终图无环。
5. Gallery 编辑内容使用发布快照；GPS 读取来源当前值，不要求重新发布。
6. 相册自身与全部已发布祖先控制公开资格；源资源当前可用性、来源范围和位置策略在请求时校验。
7. 后台独立认证；MVP 公众免登录，普通访客账号功能后续增加。
8. 先交付两组真实视觉方向，用户选定后实现完整 PC／移动体验。

## 被本决策替代的早期讨论

| 早期设想 | 替代原因与当前选择 |
|---|---|
| 一个 Publication 对应一个 Immich Album | 不符合跨来源选片；改为独立 Gallery Album，无 source_album_id |
| 移出 Immich 来源相册就停止 Gallery 公开 | 原相册不是公开授权边界；Asset 本身有效即可保持 Gallery 成员 |
| GPS 固定在发布快照，重新发布才更新 | 用户希望统一在 Immich 管理位置；改成动态读取 |
| 地图不在 MVP | 地图是用户明确强调的浏览入口；加入基础全站和相册地图 |
| 相册只有单层 | 用户需要国家／城市／专题层级；加入单父级树 |
| 简单放 parent_album_id 到在线主表 | 会导致草稿调整改变前台；父级放入 draft/release |

## 代价与后续关注

直接依赖上游数据库，需要持续维护契约测试；独立 schema 不保证没有结构漂移问题，必须实测。GPS 动态读取意味着公开地图随来源变化；Gallery 文案依然稳定。继承下线影响整条分支，后台必须明确展示影响范围。图片缓存必须经过动态授权，MVP 优先正确性，后续 CDN 需要单独决策。

此文档记录已接受的方案依据，不表示上述代码已实现。后续改变通过新 ADR 替代，不删除历史依据。
