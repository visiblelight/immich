## 2. Git 策略

仓库已经是用户 fork，不重新 git init，也不删除原有历史。

| 名称 | 职责 |
|---|---|
| upstream | `https://github.com/immich-app/immich.git`，官方只读来源 |
| origin | 用户 fork |
| main | 上游 main 的干净镜像，不合入 Gallery 业务 |
| codex/gallery | Gallery 长期产品集成分支 |
| codex/gallery-功能名 | 从产品分支开始的短期功能分支 |
| codex/upgrade-immich-版本 | 在当前产品基线上验证指定官方版本 |
| gallery-v0.1.0 | Gallery 独立交付标签，不重用 Immich 的版本号 |

初始化按顺序：

1. 记录现有 diff 和未跟踪文件，保存可恢复备份，避免把用户未提交内容丢掉。
2. 配置 upstream 并 fetch，核对提交来源与标签，不自动把 main 最新状态部署到本地。
3. 从当前提交创建 codex/gallery；记录本轮文档和已有数据库参考文档的独立提交。
4. mise.lock 修改先保留，不直接还原或混入 Gallery 初始提交；核实其来源及工具链实际需求，再作为单独变更处理。
5. 在产品分支形成已确认的需求、数据库和工程约定，后续功能小步提交。
6. CI 只新增 Gallery 所需检查；不直接启用 fork 中需要上游专用密钥、发布权限的 workflow。

main 将来跟进官方 main 与产品选择稳定版本是两件事。升级产品时合并被选中的官方标签／提交，不随手合入可能已经更超前的 main。已有共享产品分支不强制 rebase 或 force push。

本轮文档不触发远程推送、仓库设置或生产发布。正式开发中的远程操作按后续明确授权执行，本地分支和提交在开发范围内管理。

## 3. 基线和升级

当前开发可以先验证已有源码／数据库，不让较旧版本连接已迁移的本地库。如果适合的稳定标签早于当前 RC，需在隔离工作目录、独立数据库及媒体样本中重新建立基线；不能通过直接 git checkout 然后复用原数据库实现降级。

每次升级：

1. 记录当前 Immich 提交、镜像 digest、Gallery 标签、迁移版本和媒体路径。
2. 建立升级分支、数据库副本和隔离 Compose 项目。
3. 阅读官方变更说明，合并目标版本，解决代码和依赖锁冲突。
4. 运行 Immich 启动／迁移检查和 Gallery 契约、权限、发布、地图与媒体用例。
5. 验证对应备份可恢复到原版本环境，再形成升级报告和集成提交。
6. 通过后才将产品标记为支持新基线。代码切回旧版本不能替代数据库恢复。

首期至少演练一次真实、官方支持的前进升级路径。可在隔离环境使用较早兼容版本到目标版本的路径；若没有可用前进路径，该验收项保持未完成并记录原因，不能用伪造 schema 测试冒充真实升级。

## 4. 阶段安排

| 阶段 | 主要工作 | 交付物与通过条件 |
|---|---|---|
| 0：方案设计 | 完成独立文档、数据字典、MVP、Git 与验收计划 | 已获用户确认 |
| A：工程基础 | 分支、开发约定、工作区包、配置样例、基础 CI、版本记录 | 已完成本地验证；GitHub CI 配置待推送后运行 |
| B：数据与权限验证 | 来源白名单、同库 schema、受控视图、媒体读取、GPS 最新读取、上游 schema drift 验证 | 已完成隔离验证，含 1 万条合成位置；见[阶段 B 验收](phase-b.md) |
| C：视觉方向 | 两组 PC／移动首页与相册关键画面，选定后补看图器和地图交互 | 两组方向已可评审，等待用户确认；见[阶段 C 记录](phase-c.md)，确认后继续交互稿 |
| D：后台闭环 | 独立登录、相册树、跨相册选片、文案、游记、预览、发布、站点设置 | 后台可完成标准验收故事；数据库迁移和数据字典同步 |
| E：公共体验 | 全部前台页面、两端看图器、地图、分享、SEO、错误状态 | 真实照片下的视觉与交互验收通过 |
| F：部署与交付 | Compose、三个域名路由、健康检查、恢复和升级演练 | 一条命令可启动；整体验收通过；形成版本与操作手册 |

依赖顺序：方案确认 → A/B；视觉确认后进入完整 E；D 的预览与 E 复用渲染组件。A/B 暴露架构阻碍时先解决或更新决策，不在未经验证的权限模型上堆页面。

本轮不提供没有依据的工期数字；完成 A/B 后按实际依赖安装、样例规模与视觉迭代工作量补充估算。进展记录按验收结果，不以生成文件数量计完成度。

## 5. 必须验证的用例

| 编号 | 用例 | 预期 |
|---|---|---|
| AUTH-01 | 登录、退出、修改密码、停用账号 | 无效会话不能访问后台；修改密码撤销旧会话 |
| AUTH-02 | 直接请求后台写接口、跨来源表单、登录爆破 | 校验角色与来源，限流；不只靠页面隐藏按钮 |
| SRC-01 | 白名单外照片混在共享相册中 | 筛选、手工提交 ID、媒体接口均拒绝 |
| SRC-02 | 跨 Immich 相册多选，换筛选与翻页 | 已选集合保留，同一 Asset 不重复加入 |
| CONTENT-01 | 同 Asset 加入两个 Gallery 相册 | 标题描述独立，草稿互不覆盖 |
| CONTENT-02 | 两个窗口并发保存、照片排序 | 版本冲突可识别，不丢编辑；顺序无重复 |
| PUB-01 | 草稿修改与发布中途失败 | 线上保持完整旧版，事务不留下半发布状态 |
| PUB-02 | 正文引用已移除照片、封面失效 | 发布报错可定位；运行时不泄露失效资源 |
| TREE-01 | 两节点／多节点循环、并发互相移动 | 拒绝循环；草稿树和候选公开树均验证 |
| TREE-02 | 只发布部分移动、批量排序 | 只变更选中内容，最终公开树合法，顺序稳定 |
| TREE-03 | 父级下线、恢复、子级单独 offline | 页面、直链、封面、媒体、地图都遵守祖先状态；恢复提示正确 |
| GPS-01 | 第比利斯改成巴统，刷新地图 | 聚合和点位置更新，无需重发，文案和成员不变 |
| GPS-02 | 无坐标、越界、隐藏、近似模式 | 不泄露精确位置；按脱敏坐标聚合与统计 |
| GPS-03 | 同 Asset 在多相册出现，位置模式不同 | 范围内去重正确，入口只包含允许公开的出现位置 |
| MEDIA-01 | 移出 Immich 相册 vs 回收／锁定 Asset | 前者不影响；后者后续请求立即拒绝，包括缓存命中 |
| MEDIA-02 | 伪造 photoId、路径穿越、符号链接、raw 请求 | 拒绝；无数据库授权时不能绕过读文件 |
| MEDIA-03 | 编辑版预览、重建缩略图、源文件缺失 | 选对 isEdited，版本缓存失效，不回退未授权原片 |
| UI-01 | 手机、平板、桌面；横竖与长标题内容 | 没有横向溢出、遮挡、错位；正文和图片保持可读 |
| UI-02 | 看图手势、键盘、直链、返回位置 | 操作可预测、焦点正确、缩放不误切图 |
| DEPLOY-01 | 空环境初始化、重复启动、数据库短暂断开 | 迁移幂等、健康检查可信，内容与账号持久化 |
| DEPLOY-02 | 合并 Compose、域名和端口检查 | 三入口正确，公共入口不暴露数据库和后台源端口 |
| UPSTREAM-01 | Gallery 对象存在时 Immich 启动与迁移 | 无新增结构漂移故障，核心服务正常 |
| RESTORE-01 | 一致数据库和媒体备份恢复 | 相册／用户／源资源对应，权限和发布状态保留 |

测试按风险分层：纯规则用单元测试；PostgreSQL 约束、角色和事务用集成测试；关键用户闭环用浏览器端到端测试。纯文字／样式微调采用实际页面检查，不写镜像实现的低价值测试。

## 6. 性能与视觉验证口径

- 页面按需加载，不一次请求整个相册所有大图；图片尺寸声明与 srcset 按实际容器选择。
- 用一个包含至少 200 张样例照片的长相册、三级以上树和跨相册重复 Asset 检查分页与内存；性能样例在隔离环境生成，不污染真实图库。
- 地图使用服务端 bbox/zoom 聚合；至少使用 1 万条合成位置记录验证完整计数、输出上限和查询计划，照片二进制可复用测试样本。
- 记录测试机器、网络模拟、样本量、首屏资源量、LCP/布局偏移、查询耗时与内存。A/B 阶段测量后补充具体预算，不能提前把无测量指标写成已达成承诺。
- 视觉检查覆盖 320、390、768、1280、1920 CSS px 和至少一种真实移动浏览器环境；模拟触摸不能替代所有真实手势验收。
