# 人工确认拍摄地点时区交付

2026-11-01，确认范围见 [ADR 0026](../decisions/0026-manual-capture-destination.md)。用户已授权验证后发布生产；实现和本地验证已完成，生产验收记录待补充。

## 实现

- 后台“确认拍摄时间”将相机时区与逐张照片的地点时区分开。已核对地点可沿用，无效 GPS 的 Immich 地点记录仅作为候选，默认留空，主动选用后才参与换算。
- 服务器验证每张手动地点时区，支持 IANA 历史规则或明确 UTC 偏移。一个批次任一照片无效则整批回滚；预览不落库，改输入后旧预览作废。
- 只确认相机时区时保留 `timeZone=null`，避免把相机时间当作当地时间。前后台根据已确认时刻与钟表的差值显示相机 UTC 偏移，自动行程继续排除未知当地日期。
- 复用现有 `capture_correction.resolved.timeZone`，不修改证据指纹、不新增数据库迁移或依赖。旧客户端省略地点参数时沿用证据地点；新客户端显式传 null 表示只确认相机时区。既有确认继续生效。
- 本地 `/design/capture-times` 使用已只读核对的四张照片字段，共用实际表单和预览组件，不保存生产照片到开发数据库。生产继续禁用 design 路由。

## 兼容和回退

发布更新前后台应用即可，维护采集脚本不变。旧代码同样可以读取已保存的手动地点时区；只确认相机时区的记录在旧代码中会少显示 UTC 偏移，但真实时刻不变。可通过“停用校正”逐项恢复 Immich 原记录，不需要整库恢复。无原片、缩略图、OSS 或内容关联回滚步骤。
