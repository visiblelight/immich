# 拍摄时间确认复用与后台核验

状态：2026-11-01 本地实现及完整回归通过，用户已验收并授权提交、推送和生产发布；生产结果待发布后记录。需求见 [ADR 0028](../decisions/0028-capture-confirmation-reuse.md)。

## 实现

- 只补充、修改或移除 GPS，且原始时间和时间证据不变时，重新采集后复用此前人工确认的相机时区，按新地点换算。后台显示复用说明；已有更新状态和自动刷新继续生效。
- 原始时间变化、证据冲突、停用或无法证明旧时间基线时，不复用旧确认。之后再改变 GPS 也不会使已失效的确认重新生效。仍允许独立可信证据按既有规则自动换算。
- 到访管理按国家/省份名称排列，同地点按日期倒序，排序先于分页。保留人工到访成员和日期，不自动合并。说明新增或补全信息的照片仍自动整理，可显式勾选合并。前台旅行时间排序不变。
- 拍摄时间管理为仅文章公开的照片补上文章内直达链接，打开对应照片看图器（含图片组和封面）；相册公开照片仍优先使用相册链接。未公开照片提供后台查看入口，不绕过公开资格检查。
- 公开链接在单次查询中汇总后匹配，避免逐张重复扫描公开资格视图造成大图库超时；不放宽数据库的运行超时或角色权限。
- `/design/capture-confirmation` 使用虚构数据演示补 GPS 与源时间改变两种结果，不改动真实图库。

## 数据与回退

0018 仅新增 Gallery 时间签名列，并为完整来源仍匹配的记录补齐基线。迁移不写 Immich，不修改相册、照片组、文章关联和人工到访。已过期且无独立时间基线的历史证据不猜测复用。

应用应先迁移再重启，后台 readiness 要求新列。旧应用可忽略新增列和 resolved 标记，不需删除数据回退；回退后原先的来源变化失效规则恢复。时间采集器依旧只读原片、sidecar 和源数据库。
