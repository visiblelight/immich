# 拍摄时间更新状态与自动刷新

状态：2026-11-01 本地实现与验证通过，用户已验收并授权随确认复用一同发布；生产结果待发布后记录。需求见 [ADR 0027](../decisions/0027-capture-update-state.md)。

## 已实现

- GPS/来源变化后显示“正在更新拍摄时间”，移出“待核对”；“更新状态”单独包含处理中及读取失败，页面顶部提示当前数量。
- 页面可见时闲置 15 秒、处理中 2.5 秒查询；回到窗口立即查询。发现来源变化时提交现有优先读取队列，最多 100 张一批，同一来源签名不重复提交。弹窗、提交中、隐藏及离页暂停，防止打断人工输入。
- 完成后自动刷新筛选结果、数量、页码和选中项；相同来源重复读取不会更改拍摄时间。失败及过期可手动重试，请求失败不会无限入队；断网恢复后更新提示。
- 没有有效 GPS 但有相机钟表的照片保留原始时间，标注时区未知，不因为缺少地点增加人工待办。已明确源时区、但没有目的地时区的照片继续保留已验证的排序时刻，不改变既有人工行程。
- 后续全量扫描取得新证据后，不再被更早的失败请求遮蔽。仅管理查询忽略已被取代的失败，保留队列记录。

## 兼容和边界

无数据库迁移，不修改 Immich 表、原片、缩略图及元数据，不修改内容关联。计算与人工校正保护规则不变；旧代码回退无需数据回滚。未打开管理页仍依赖现有后台定时扫描，不能保证修改 GPS 的瞬间已完成读取。只有位置仍不足以证明未记录的相机时区；真正缺少源时间依据或证据冲突仍需核对。

后续用户已确认仅 GPS 变化时复用相机时区；该补充通过独立时间签名验证，不沿用旧当地时间，见 [确认复用交付](capture-confirmation-reuse.md)。
