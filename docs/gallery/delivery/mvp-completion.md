# MVP 功能与运行收尾记录

2026-09-11。用户授权继续后续流程，前后台视觉细节暂缓。本文追加实际结果，不改变已接受的产品范围；历史阶段记录不作为当前功能清单。

## 本轮完成

- 照片独立地址 `/albums/<slug>/photos/<photoId>`，刷新保留大图，切换更新地址，关闭回到对应分页和照片焦点。无效 ID、移出当前发布版本、相册或祖先下线均拒绝访问。
- 目录／子相册每页 24 本，照片每页 48 张；SSR 支持照片分页参数。仍按当前相册加载照片元数据，并非数据库游标分页；单册编辑上限 1000 张。
- 管理员昵称保存、站点最多 10 个联系链接保存并应用；独立管理员创建／重置／停用／启用维护命令，撤销会话并保护最后一个管理员。复用已有表和字段，无新增迁移。
- 图片输出使用进程内 64 MiB／最多 256 项缓存，以内容摘要区分衍生文件；编码最多并行 2 个、排队最多 32 个，待编码输入上限 64 MiB。每次媒体请求先做数据库授权和路径／文件校验，HTTP 继续 `no-store`。缓存不授予访问权。
- 独立 Gallery Docker 镜像、public/admin Compose、三个域名的代理模板、账号和备份恢复操作手册。

## 验收结果

- `gallery:check`、`gallery:build`、`gallery:test`、`gallery:smoke` 通过；5 个配置／角色单测，Svelte 0 错误／警告。
- PostgreSQL／HTTP／恢复共 20 项测试（19 子用例及父用例）通过。新增昵称／联系链接、危险链接拒绝、照片直链撤销、账号维护权限与旧会话撤销、最后管理员保护。
- 240 个不同 Asset 的合成长相册：发布约 526 ms，第二页 HTTP 约 55 ms；24 路缩略图请求冷／热约 100／93 ms。首次 HTML 只渲染 48 个照片格位。样本使用同一合成图片，因此这些数字是本机功能与并发回归记录，不是复杂原片、移动网络或生产容量承诺。
- 完整 custom-format 数据库 dump 约 1.75 MB，恢复到隔离新库；8 本相册、10 个发布版本、10247 条发布照片、2 位合成用户，以及正文摘要一致。恢复后撤销旧会话，受限公开角色可读取 240 张照片的相册及图片。角色已在测试集群存在；未模拟真实磁盘损坏或跨大版本恢复。
- 本地浏览器验证真实已发布相册：点击进入直链、刷新、下一张、Esc／按钮关闭、分页返回焦点。390px 手机视口下图片加载正常，无页面横向溢出；这不替代实体手机浏览器验收。
- Gallery 镜像构建、Compose 强制重建后两个服务 readiness、真实相册与图片、管理员登录／退出、设计原型默认关闭均通过。容器使用非 root、只读文件系统和只读 thumbs，运行角色不包含迁移／owner 凭据。
- 当前 Immich 原始迁移／结构检查通过，0 drift。另从官方候选 v3.2.0 的固定 commit `1b6098c9dbfffe978bec2d414606ed7a4c8e019a` 提取并编译原始迁移／schema 代码，在含 Gallery 的隔离库执行成功，0 drift。该候选相对当前 RC 没有迁移／schema／DatabaseRepository 源码变化，因此这是候选数据库兼容性检查，不是发生了真实结构演进的整应用升级演练。
