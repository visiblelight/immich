# 相册与相片连续浏览交付

2026-10-18：按 [ADR 0020](../decisions/0020-continuous-browsing.md) 完成本地实施与验收，用户已确认效果并授权提交、推送及生产发布。发布结果待本次流水线完成后记录。

## 实现

- 相册每批 24 本，照片每批 48 个列表项目；相册内照片组为原子项目，整个组连同封面和成员一同返回。全部相片页沿用按来源照片去重的独立照片语义。
- 列表底部距离视口 700px 时触发追加；同一列表只运行一个请求，大图切换可等待已在进行的预取。追加不替换旧网格，封面及照片加载占位，错误显示重试，完成后显示简短提示。
- `/api/browse` 使用与首屏相同的 server-only 加载器和公开投影，响应 `private, no-store`。游标由排序值和稳定 ID 组成，删除上一批边界项目后仍可续取。分页、游标、照片定位都不构成访问授权。
- 首屏和追加响应只包含当前批次及必要的祖先信息。后端相册统计/搜索、照片成员资格和筛选聚合仍扫描符合公开条件的元数据；不是所有 SQL 都已改成常数开销，也不是预加载全量照片 DTO 后在浏览器分页。
- 搜索、排序和筛选改变会开始新列表并取消旧请求；搜索保留输入焦点。浅路由记录大图状态，浏览器返回可关闭大图或恢复列表。
- 滚动停顿时用 `replaceState` 更新可见项目锚点，刷新直接定位其所在批次，不从第一页逐批下载；旧 `page` / `albumsPage`、`#photo-ID` 和独立照片路径仍可访问。直接从中间批次进入时提供加载前面内容的入口。
- 会话内最多缓存 6 个列表、保留 2 分钟；单列表超过 600 张照片或 240 本相册时只保留位置。缓存不写入 localStorage；恢复前核对新响应的数量及当前批次，媒体请求继续实时校验资格。

## 验证

- `gallery:check`：0 错误、0 警告；`gallery:build` 和 `gallery:test` 通过。
- 隔离 PostgreSQL + 生产构建 HTTP 验收：26 项通过；使用合成数据，不接触开发库/生产库，Immich schema drift 为零。
- 240 张合成照片验证每批 48 项、完整续取无重复、深位置定位、全局相片去重、下线撤销和图片权限。
- 26 本合成相册验证 24 + 2 两批及完成提示；跨第 48 张照片的三成员组验证整组同批返回，下一批无重复。浏览器验证相册追加、全部照片追加及 390px 下无横向溢出。
- 可选 Playwright 验收入口：将 `GALLERY_BROWSER_CHECK_SCRIPT` 指向 `deployment/gallery/scripts/browse-browser-check.cjs` 后运行 `gallery:test:db`。已有 Playwright/Chromium 可通过 `GALLERY_PLAYWRIGHT_MODULE` 和 `GALLERY_CHROMIUM_PATH` 指定；未设置时不要求浏览器依赖。覆盖自动追加、失败重试、刷新锚点、大图跨批次、返回恢复、排序重置及 390px 手机布局。

## 兼容与本地预览

本地相册入口 `http://127.0.0.1:3100/albums`，相片入口 `http://127.0.0.1:3100/photos`。少于一批时直接显示全部；长列表行为使用隔离合成数据验证。

无数据库迁移，无依赖或工具链版本调整。生产未变更；现有 Immich 3.3.3 本地升级配置和用户原有 `mise.lock` 修改保留。回滚应用代码即可恢复原分页界面。
