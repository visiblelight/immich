# Gallery 接手入口：不依赖聊天记录继续开发

核对日期：2026-11-03。适用于换电脑、丢失聊天记录，以及 Codex、Claude 或其他 agent 接手。本目录记录当前事实和操作入口，不是新的产品授权；文档中的部署、恢复和数据修改步骤不能直接视为用户要求执行。

## 第一次接手先做什么

1. 读取仓库根 [AGENTS.md](../../../AGENTS.md)，再读本文和[当前状态](current-state.md)。Claude 的入口为根 [CLAUDE.md](../../../CLAUDE.md)，规则仍以 AGENTS.md 为唯一维护来源。
2. 确认所在仓库、分支、工作区修改。产品在 `codex/gallery`，`main` 只是 Immich 上游镜像。先保留原有修改，不执行 reset、clean 或初始化数据库。
3. 读[架构与产品约定](architecture-and-product.md)，找到本次功能的代码、ADR 和交付记录。`/design/*` 只是样稿，不能当作真实功能已经接通的证据。
4. 换机先按[本地开发与迁移](local-and-transfer.md)恢复配置、数据库和媒体；只是继续现有机器工作则先检查服务，不重复安装、初始化或迁移。
5. 按[开发与验证流程](development-workflow.md)实现、检查和提供本地验收。发布需已有用户授权，并按[生产运维](production-operations.md)核对迁移、镜像和回退范围。

## 文档如何取信

| 需要知道什么 | 首要依据 | 注意 |
|---|---|---|
| 用户已接受什么行为 | 最新用户指示、相关 `decisions/` ADR | 新 ADR 可以替代旧 MVP 限制；实现现状不自动变成新需求 |
| 实际有哪些实现 | 当前代码、迁移、对应 `architecture/` 数据字典 | 代码与已接受需求不一致时应明确指出，不擅自改需求 |
| 哪些已经验收或上线 | `delivery/` 中最近的**带日期**验收、实际运行版本 | 同一个文件前面的“待上线”可能是旧阶段记录 |
| 当前电脑和服务器情况 | 本目录状态快照，再现场只读核对 | 端口、计数、磁盘、进程状态都可能变化 |
| 可执行命令和依赖版本 | 根 `package.json`、`mise.toml`、`deployment/gallery/` | 历史日志中的一次性命令不应直接重跑 |
| 密码、连接串、密钥 | 私有配置或授权的凭据管理渠道 | 文档只记录用途与路径，不保存实际值 |

`docs/gallery/README.md` 是全部文档索引；`architecture/` 解释结构，`decisions/` 保存决策，`delivery/` 保存实施与验收证据，`development/` 保存专项操作方法。早期 MVP 文档是历史背景；本目录注明的现状可用于识别旧描述，但不能代替实际检查。

## 可以交给新 agent 的开场指令

> 这是已有生产用户和真实照片的 Immich fork / Gallery 项目。请先读根 AGENTS.md、docs/gallery/handoff/README.md 和 current-state.md，再读取本次功能的 ADR、数据字典和交付记录。先检查分支、未提交修改、工具链和本地服务，保留所有既有数据和修改。Gallery 工作不能修改 Immich 原片、衍生图、元数据或上游表。不要重新初始化数据库，不要启动无关项目，不要把设计样稿当作真实接入。先向我说明当前状态与本次任务相关的缺口，再按已授权范围继续；没有发布授权时只在本地实施和验证。

新任务仍需另外给出具体目标，例如“启动本地环境”或“修复某个页面”。上面的指令不授权生产发布。

## 换机必须带走什么

Git 仓库包含代码和文档，**不包含真实图库、数据库、文章上传素材、登录凭据、发信密钥、SSH 私钥、未提交修改和验证截图**。仅克隆仓库无法恢复现在的本地环境。

至少完成三件事：

- 保存 Git 已提交历史，以及未提交文件和补丁；确认交接文档本身也已纳入需要迁移的副本。
- 私下备份完整数据库、角色、媒体、文章素材和运行配置，记录版本与校验和，并在新机器隔离恢复验证。
- 恢复 GitHub、服务器 SSH、阿里云的访问能力；保留生产配置和密钥，不因换电脑就重新生成或覆盖。

详细清单见[迁移指南](local-and-transfer.md)。本次整理没有执行备份、恢复或生产变更，也不代表已经建立异机备份。

## 以后如何保持这份交接有效

每次功能完成：更新相关 ADR/数据字典/交付记录；每次上线：更新当前状态中的应用提交、schema 版本和验收链接；每次改部署或路径：同步迁移及运维指南。只记录验证过的结果，未验证事项明确标记。旧版本和旧恢复证据保留，避免后来的人把“没有实现”和“后来已完成”混淆。
