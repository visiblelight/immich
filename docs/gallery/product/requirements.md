# Gallery MVP 需求与页面流程

状态：按用户反馈更新。版本：0.2，2026-09-11。

范围调整见 [ADR 0002](../decisions/0002-albums-first.md)。独立用户、相册和发布规则保留。

## 1. 产品目标

建设一个单站点的摄影展示平台。相册兼具照片集合和游记文章的属性；支持国家、城市、专题等层级；同时提供专门设计的 PC 与移动浏览体验。Immich 是集中资源库，Gallery 管理展示内容，不复制一套原片上传与分类管理系统。

标准流程：处理照片 → 上传 Immich → 在 Immich 整理相册／标签／GPS → 登录 Gallery → 跨筛选结果选片 → 建立 Gallery 相册和层级 → 编写游记及照片文案 → 预览 → 发布 → 公众浏览相册、照片和文字介绍。

## 2. 术语与数据归属

| 对象 | 定义 |
|---|---|
| Immich Asset | 一份原始媒体资源及其元数据；MVP 只选可生成可浏览图片的 IMAGE |
| Immich Album | 后台选片的筛选条件，不是 Gallery 相册的来源边界 |
| Gallery Album | 有独立地址、封面、游记、直接照片、子相册和发布状态的内容主体 |
| Gallery Album Photo | 某张 Asset 在某个 Gallery 相册里的使用记录，有自己的标题、描述和顺序 |
| Draft | 正在编辑的内容，不向公众开放 |
| Release | 点击发布产生的内部内容快照，不是另一个产品对象 |
| 有效公开 | 相册自身及每个已发布父级均上线，且具体照片满足资源可用条件 |

原片、GPS、相机元数据和 Immich 标签由 Immich 维护；Gallery 文案、选片关系、顺序和公开规则由 Gallery 维护。两个系统的用户 ID 无绑定要求。

## 3. MVP 范围

### 3.1 用户与账号

- 初始化创建一个 Gallery 管理员，无默认密码；提供登录、退出、昵称修改、密码修改和服务器端重置命令。
- 数据模型包含 admin/member，但本期不开放访客注册和前台登录入口。
- 后台页面及接口均校验权限；会话独立于 Immich，密码修改后撤销已有会话。
- 普通浏览者免登录访问公开内容。

### 3.2 后台页面

| 路由建议 | 页面／模块 | 必须完成的操作 |
|---|---|---|
| `/login` | 登录 | 独立账号登录、错误提示、过期会话跳转 |
| `/albums` | 相册管理 | 树形浏览、标题搜索、状态筛选、创建顶级或子相册、查看直接上线与被父级阻断状态 |
| `/albums/:id/edit` | 相册编辑 | 标题、简介、详细游记、封面及焦点、父级选择、同级顺序、独立地址 |
| 编辑页的资源选择器 | Immich 选片 | 按相册、标签、拍摄日期、文件名过滤；分页；跨筛选连续选择；已加入提示；确认加入 |
| 编辑页的照片面板 | 单张内容管理 | 排序、移除、标题、描述、alt、位置策略；查看源图信息和资源失效提示 |
| `/albums/:id/preview` | 后台预览 | PC／移动宽度预览，真实前台组件渲染；显示草稿层级和生效差异 |
| 编辑页的发布面板 | 发布与下线 | 差异摘要、校验、发布、更新、下线；展示层级移动和父级恢复的影响范围 |
| `/settings/site` | 站点设置 | 站点名、基础说明与联系链接；保存并应用；首页配置暂缓，关于选篇随未来文章模块设计 |
| `/settings/account` | 账号设置 | 昵称、密码、退出 |

同级拖动排序先保存受影响相册的草稿；提供一次“发布这组调整”，原子应用整组排序。移动父级同样先进入草稿，不即时改变公共导航。

选片初始结果只包括白名单所有者的可用照片。相册和标签过滤不能扩大资源范围。标签先使用 Immich 标签表，不把 EXIF 自由文本标签混成同一种筛选。

### 3.3 文本与照片内容

- 相册简介为纯文本；详细描述为结构化富文本游记。
- 详细介绍块：标题、段落、引用、列表、分隔线；支持基本加粗／斜体及安全链接，不包含单图或双图。
- 所有照片集中在相册内容区；右侧详细介绍不插图。父相册可自行选片，也可以只有子相册。
- 每张照片有独立标题与纯文本多段描述；第一版不再为单张照片提供第二套复杂富文本编辑器。
- Gallery 标题／描述初始为空；文件名可作为后台占位提示，但不会自动发布为标题。Immich 描述只读参考，不自动同步或覆盖。
- 同 Asset 跨相册的文案互不影响。单相册不能重复加入同 Asset。
- 封面可来自本相册直接照片；纯父相册可明确选择已发布后代照片为封面，发布时校验。引用来源后来失效则显示中性占位，不泄露失效图片，也不随机换封面。

### 3.4 前台页面

| 路由建议 | 内容 | 关键行为 |
|---|---|---|
| `/` | 站点入口 | 首版进入相册目录，不单独制作首页 |
| `/albums` | 相册目录 | 顶级相册固定列数网格，不使用瀑布流；不把所有层级平铺；分页 |
| `/albums/:slug` | 相册详情 | 面包屑；左侧子相册与直接照片，右侧富文本文字介绍；无地图入口 |
| `/albums/:slug/photos/:photoId` | 照片详情／看图器 | 尽可能大的完整图片、标题、描述和 EXIF；信息可隐藏；正式实现支持直接分享或刷新打开 |
| `/about` | 关于 | 当前静态文章示例；未来从后台文章模块选择一篇文章展示 |

照片详情是可深链接的真实状态，可复用同一看图器。当前发布版本移除该 photoId 后返回不可用页，不暗中跳转到别的相册副本。

关于选篇是未来文章模块需求，本轮不新增文章表；具体页面、字段和发布规则在该模块设计时确定。

EXIF 按白名单公开相机、镜头、焦距、光圈、快门、ISO 等参数；不原样输出整份 EXIF，GPS 仍受位置公开策略约束。

### 3.5 PC 和移动端

| 体验 | PC | 移动 |
|---|---|---|
| 相册目录 | 固定列数网格，统一封面比例 | 当前预览固定两列，保持触摸尺寸 |
| 相册详情 | 左侧子相册和照片，右侧纯文字富文本介绍 | 子相册／照片网格，介绍可展开，保持阅读位置 |
| 看图器 | 方向键、Esc、点击缩放、焦点管理 | 滑动、双击／捏合缩放、明确关闭、缩放与切图手势协调 |

键盘关闭或触摸返回后恢复相册位置；分享链接直接打开时有返回相册的明确入口。包含加载、空相册、无定位、404、图片失效与网络失败状态。

### 3.6 相册层级与未来地图

地图页与后台地图面板移出 MVP。以下地图规则作为未来扩展保留，已验证的底层权限和 GPS 读取不回退。

- 相册地图汇总自己和有效公开后代的照片；全站地图汇总全部有效公开照片。
- GPS 实时读 Immich，刷新请求更新，不要求重发相册；打开的页面不保证实时推送。
- 去重依据是 Immich Asset，成员照片按当前地图范围与公开策略过滤后聚合。
- 聚合按坐标和缩放级别，不按相册名称或可能过期的城市文字。
- 父相册页面展示子相册入口和直接照片，不自动平铺全部后代；照片数明确标注“本相册”与“含子相册”，汇总数字按 Asset 去重。
- 相册树单父级；有效公开依赖祖先；细节以 [发布规则](../architecture/publication.md) 为准。

## 4. 明确不在 MVP 的范围

独立首页、全站／相册地图及后台地图面板、访客注册／登录、留言、评分、收藏、邮件验证和找回、第三方登录、复杂管理员权限界面、多租户、相册多父级、视频及 Live Photo 专用播放、原片下载、轨迹与路线规划、位置反向解析平台、通用页面搭建器、主题市场、深浅色双主题、定时发布、历史版本管理界面、PWA 离线与原生 App、交易和客户选片。

不做这些页面的空壳；只保留合理的数据扩展边界。

## 5. 标准验收故事

1. 用测试账号在 Immich 两个相册放置照片 A/B/C，另有未挑选照片 P。
2. 在 Gallery 创建“格鲁吉亚”，再建“第比利斯”和“巴统”；父级有总游记，子级各有游记。
3. 从不同 Immich 相册选 A/B 到第比利斯，选 C 到巴统，为 A 填写 Gallery 标题描述。
4. 同时在父级选 A，编写另一套图注，验证两处互不覆盖。
5. 自顶向下发布，PC 与手机能浏览层级、游记与相片；P 不出现在任何公开响应中。
6. 打开照片大图，查看 Gallery 标题、描述和允许公开的 EXIF；手机收起／展开信息，关闭后回到原位置。
7. 保存新草稿，公开页面不变；发布后更新；下线父级后子相册深链接、照片和封面均不可访问。
8. 将 B 移出 Immich 原相册，Gallery 不受影响；将 B 放入回收站，Gallery 后续请求不再提供 B。

这些是未来实现的验收要求，不是当前测试结果。
