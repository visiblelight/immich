# 草稿、相册树与发布规则

状态：已确认。版本：0.1，2026-09-10。

## 1. 两棵树与一个稳定身份

Gallery Album ID 与公开 slug 表示稳定身份。后台编辑树来自 album_draft.parent_album_id，公众导航树来自各相册 current_release 指向的 album_release.parent_album_id。保存草稿不会改变公开树。

一个相册可以同时包含自己的照片与多个子相册；每个相册最多一个父级。成员关系不受 Immich 相册、标签和 GPS 更新影响。

公开 URL 固定为 `/albums/:slug`，层级通过面包屑体现，不把完整父级路径编码到 URL。首次发布后 slug 固定，避免 MVP 引入重定向历史管理。

## 2. 状态与有效公开

| 内部状态 | 用户理解 | 公开行为 |
|---|---|---|
| draft，无 release | 从未发布 | 不可访问 |
| published，有 current_release | 已上线 | 还需所有祖先上线 |
| published，但祖先 offline | 因上级下线暂不可见 | 包括直接链接在内全部阻断 |
| offline，保留 current_release | 手动下线 | 不可访问 |

“有未发布修改”通过 draft.version 与 current_release.source_draft_version 比较，不另造状态字段。GPS 改动不使草稿变脏；源资源失效另显示警告。

有效公开相册必须能沿当前发布父链到达顶级，链上每个相册均 published、存在有效 current_release，并且无循环。结构异常或无法读取时拒绝返回该分支，不退化成无父级公开。

## 3. 发布的校验

发布前校验：

1. 管理员身份、账号状态、期望的 album.version/draft.version/tree_version。
2. 标题、slug、文档结构、照片顺序、位置策略是否合法。
3. 全部直接照片仍属于来源白名单，且是可浏览、非删除、非锁定的资源；预览／缩略图可用。
4. 正文 photoId 必须属于本次直接照片集合，标题和描述完全来自 Gallery。
5. 封面属于本册直接照片或有效公开后代，并且资源仍可用。空封面合法，解决纯父相册首次发布的启动依赖。
6. 父级已经有效公开，或在同一个明确选中的发布批次里先于子级生效。
7. 草稿树、拟提交的最终公开树均无环；移动不会把相册挂到自己的后代。

层级不以固定三层限制，页面支持任意合理层级；递归查询设置执行超时，遇到异常链拒绝访问并记录错误。界面通过折叠树和可收纳面包屑处理较深结构。

## 4. 事务与并发

- 树结构写入、层级发布、下线和草稿相册删除统一锁定 site 的协调行；采用 tree_version 检查客户端是否基于旧树编辑。
- 发布按固定顺序锁 site → album（ID 排序）→ album_draft（ID 排序），避免多相册操作互锁。
- 普通文案或照片保存锁定相应 draft，校验 version 后更新；不反向获取树锁。保存失败返回冲突提示，不静默覆盖另一窗口修改。
- 在锁内构造最终候选公开树并验证。只校验草稿树不足够，因为其他相册可能尚未发布其草稿移动。
- 插入不可变 release 与 release_photo，切换所有选中相册 current_release，更新发布状态与版本，写入审计，然后一起提交。
- 同级批量排序使用间隔 bigint 顺序键；发布选中的受影响相册集合并原子应用。预览列出该批次会同时带上的其他草稿修改，用户不能误以为只会改顺序。
- 失败回滚，公众继续读取完整旧版本；相册发布不应读到一半旧照片、一半新正文。

来源资源在发布校验后仍可能变化，因此公开请求永远进行当前资源资格校验，不能仅信任发布时检查。

## 5. 各操作的行为

| 操作 | 草稿 | 公开版本 |
|---|---|---|
| 修改标题、游记、照片描述 | 更新 | 不变 |
| 移除草稿照片 | 移除；正文残留引用必须修正 | 当前 release 保留，直到新发布 |
| 新增子相册 | 新增 draft | 不自动公开 |
| 发布父相册 | 创建新快照 | 不自动发布子相册 |
| 移动父级／同级排序 | 更新草稿树 | 发布对应调整后才变化 |
| 下线父相册 | 保留 | 其整条后代分支的页面、媒体、封面、地图都阻断 |
| 下线子相册 | 保留 | 不影响兄弟相册 |
| 重新发布下线父相册 | 使用当前草稿 | 发布前列出会恢复访问的已发布后代；手动 offline 的后代仍不恢复 |
| Immich 移出原相册 | 不自动改 | 无影响 |
| Immich 删除／锁定资源 | 标为不可用 | 下一次授权请求停止返回资源 |

恢复上线在 MVP 中使用明确的“发布并上线”动作，生成新 release；不悄悄恢复旧快照或批量公开全部草稿。

## 6. 相册展示、封面与地图

- 父相册正文和直接照片独立于子级；详情页提供子相册入口，不展开所有后代照片流。
- 相册地图汇总本册和有效公开后代，地图 photoId 对应可访问的具体出现位置。
- 父级的 location_mode 只控制父级直接照片，不修改后代自己的位置策略；祖先的上线状态则控制整个分支。后台明确这一区别。
- 无直接照片的父相册可以先无封面发布，再发布子相册，最后为父级选择后代封面并更新发布。
- 后代封面来源移出该分支、被下线或资源失效时，父级封面变为中性占位；后台标记封面失效。封面接口必须检查当前后代关系，不因快照里有 Asset ID 就继续读取。
- 同 Asset 在其他公开相册仍可用，不会使已下线相册的旧 photoId 路由恢复；访问必须经过当前请求的相册出现位置。

## 7. 预览

草稿预览只在 gallery-admin 的已认证会话下提供，复用前台渲染组件。预览数据和媒体 no-store/noindex，不签发任何永久公共预览链接，不依赖跨域共享 Cookie。

预览可以展示尚未上线的父子草稿，但显著标记“预览”，并显示真正发布所需的父级顺序。预览宽度切换不替代真实移动浏览器验收。

站点设置和首页精选在 MVP 中不使用这套草稿表，只有明确的“保存并应用”。未来如加入站点级草稿，应独立设计，不混入 album 发布事务。
